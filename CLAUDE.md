## Target architecture (decided)
- **Microservices (FastAPI, Python latest):** identity, catalog, inventory, order, document, notification + media-worker (GPU, rembg) + one outbox relay per service.
- **MongoDB** replica set: primary on main host (priority 10) + 2 × Raspberry Pi 5 secondaries. One database `inventory`. **Existing collection names kept.**
  Ownership:
  - identity: `accounts`, `temp`, `organisations`*, `auditlog`*
  - catalog: `product`, `xuser` (view), `misc`
  - inventory: `storage`, `history`, `stock`*
  - order: `orders` (incl. carts as `status: CART`)

  (* = new.) A service only touches the collections it owns. Transactions are allowed.
- **Kafka** (KRaft ×3) between services; HTTP only for immediate questions (order→catalog, order→inventory availability, document→order access, notification→catalog). Outbox stored on the changed document. Envelope: `eventId, type, version, occurredAt, correlationId, actorId, payload`. Key = entity id. Retry topics, then DLQ.
- **Redis**: revocation, rate limits, idempotency keys, processed-event IDs, locks.
- **nginx** at the edge; **local file volume** `/srv/sia-data` + `X-Accel-Redirect`. **Docker Compose only.**
- **Monitoring:** Prometheus + Alertmanager only (**no Grafana, Loki or Sentry**).
- **Frontends:** Vue 3 + TypeScript + **Vuetify 4** + file-based routing + **Zod 4** + Pinia; API clients generated from OpenAPI. **Android min 12 (API 31).**
- **Auth:** EdDSA JWT (access 15 min, refresh 7 d, a new refresh issued on every use), JWKS, Argon2id, cookies + CSRF (web), Bearer (mobile).
- **Hardware:** host with 16 cores / **32 GB** / 2 × 6 GB GPU (budget **29.5–31.5 GB incl. ClamAV**, very tight; 64 GB upgrade strongly recommended; every container has `mem_limit`). Staging runs on the host, on demand. Backups use restic to another CIMH site. Mail goes through **Gmail SMTP** (`smtp.gmail.com:587` STARTTLS, `printit.inc.7@gmail.com`, From name "PrintIT"; owner decision 2026-11-10); the app password goes only in the prod `secrets/smtp_password` (never in git). Login verified 2026-11-10. CI is GitHub Actions + GHCR (deploys by a self-hosted runner on the host).

## Business rules (decided)
- Roles: `admin`, `staff`, `user` only.
- Registration: verify email → **admin approval** → ACTIVE. `@cimh.edu.bb` accounts skip approval and **cannot request items**.
- Organisation is entered as free text; the admin links it to an `organisations` record. **Same-org users can see each other's requests**; only the requester or an admin can act on them.
- **No payments.** Paid request flow: SUBMITTED → QUOTING → QUOTED → **AWAITING_AGREEMENT** → ACCEPTED → PURCHASING → SHIPPED → DELIVERED (DECLINED/expired → CANCELLED).
- **Acceptance = signed agreement:** the customer chooses options → the system generates an agreement PDF (total) → the customer downloads, signs and uploads it (`signed_agreement`) → ACCEPTED. Staff verify the signature (`agreementVerified` is required for purchase orders) or reject it (back to AWAITING_AGREEMENT).
- **Supplier items ship direct** to the customer: never stowed and never tracked as units. Only CIMH-stock and Pro Bono lines are picked.
- **CIMH stock quote:** offered only for lines where stock covers the **full** quantity. Priced at catalogue cost (BBD) + admin fee; for USD requests staff enter the exchange rate. The customer picks CIMH or supplier per line. Stock is reserved at acceptance.
- **Pro Bono** (free items; the old name "NCI" is retired; legacy code still says `ncicart`/`nciStore`): SUBMITTED → APPROVED → PICKING → SHIPPED → DELIVERED, with no quote. Staff can set `probonoMaxPerRequest` per item. A mixed cart is split into a PAID and a PROBONO request. Field `product.probono`; request type `PROBONO`; events `order.probono_*`.
- Currency is BBD or USD, one per request. Quotes are valid 30 days.
- Carriers: FedEx, DHL, hand delivery. **Tracking numbers are entered manually; no carrier APIs.**
- Customers never see prices on product pages.
- Brand: logo blue `#0084C8` (4.09:1 on white, so **not for normal text**); interactive primary `#006FA8` light / `#5CC2FF` dark; Pro Bono badge `#F5C400` with ink text only.
- `product.probono` is set explicitly at product creation. Migration: legacy `sellable "probono"` → `sellable: true, probono: true`; `"yes"` → `true`; `"no"` → `false`. Product `type` values are codes `MET RAD EQUIP SUPP MISC PRO`. Carts left inactive are emptied after 180 days. Backups: 30 daily + 12 monthly.

## Implementation decisions (made while building; docs updated)
- **Codes never travel in Kafka.** `temp` keeps `codeHash` + a sealed `codeEnc`; notification-svc claims it **once** via `GET /internal/codes/{codeRef}` (5th sync HTTP call). New events `user.password_reset_requested`, `user.email_change_requested` (codeRef only).
- **Admin without MFA**: may log in, but every endpoint except `/auth/mfa/*`, `GET /me`, `/auth/logout` returns 403 `MFA_REQUIRED` (token claim `mfa`). **Service tokens** are refused on user endpoints.
- First admins come from migration; dev bootstrap = promote a CIMH account in the dev DB (`tools/e2e/identity_smoke.py`).
- **Erasure** is admin-performed on the person's request (password-confirmed), never self-service; self-service export hides staff names (role only). `svc_identity` keeps `update` on `auditlog`, used only to anonymise erased/purged people.
- Product ids keep the legacy format `<TYPE><32 hex>` (or a scanned barcode); `number` from `misc` `counter:product`. Customer reads use `product` + `PUBLIC_FIELDS` (same list as the `xuser` view). Request bodies are strict (no coercion). Each calling service gets its own `service_secret_<name>` file.
- **UI structure follows the legacy apps** (owner, 2026-11-07): every screen keeps the layout, navigation and section order of the matching legacy page (`legacy/shop/src`, `legacy/sia/src`); the Design Brief only supplies the modern look. v2 rules still override legacy content (no prices/serials for customers, Pro Bono naming).
- **Legacy data migration** (`tools/migrate/`, 2026-11-08): exports in `db/` (git-ignored, real PII). Duplicate emails (2 people, 6 extra accounts, no activity) keep the oldest/active account; account org = org on its latest order (legacy had none; 35 customers without orders have no org, admin assigns); legacy passwords work (Werkzeug hash, rehashed at first login); admins must enrol MFA at first login. Files (M08) from `db/` subfolders: 157 product images (all 83 products) + 38 generated invoices (`<id>.pdf`, `<id>_nci.pdf` → Pro Bono half) loaded; **66 uploaded order files missing** (legacy `uploads/` not in `db/`); 20 invoices of orders not in the export left out.
- **Suspended customers' carts** (2026-11-10): `blocked` on the cart (consumer of `identity.user.events`), 403 `ACCOUNT_SUSPENDED`. Defence in depth only: suspension already revokes every session, access tokens carry `sid`, and the revocation check fails closed. **Alert email**: Alertmanager can't expand env vars, so `render-config.sh` renders `alertmanager.yml.tmpl` → `alertmanager.rendered.yml` (git-ignored); re-run it + restart alertmanager after changing `ALERT_EMAIL_TO`/`SMTP_*`.
- **SIA Mobile offline queue (P8):** every scan goes through `ScanQueue` (written first, then sent, oldest first). Network/408/429/5xx = stays queued, same key; 401 = wait for the same account; other 4xx = refused (server replays it per key), M-11 Retry uses a new key. Queue is per account (screens show only the signed-in account's scans; another account's leftovers stay hidden and unsent); logout with pending scans confirms and deletes them (reversible decision). Offline, a scanned shelf is not checked (legacy shelf formats vary, BSD), so a wrong code is refused when sent. Scanning = CameraX + ML Kit live preview (legacy layout), not the Play code scanner. Room via KSP 2.3.12 works with AGP 9.4.1 / Kotlin 2.4.21.
- **SIA Mobile P8 finish:** Issue/Return live in the Pick tab (mirrors SIA web; APD M-05 changed); APD overflow menu has no Settings (none planned). Fonts bundled (Inter + JetBrains Mono variable, OFL in `assets/licenses`). Release signing = `mobile/sia/keystore.properties` or `SIA_KEYSTORE_*` env; CI signs only on `main` when the secrets exist, otherwise unsigned. The Note 10+ run must use the **signed release APK** (only it exercises the R8-minified network code).
- Org name uniqueness via `nameKey` (lower-cased) instead of a collation index. HIBP fail-open (TRD). Missing `If-Match` → 428 `PRECONDITION_REQUIRED`.
- **Inventory (P4):** new collection **`stock`** (one doc per product: counts recomputed from `storage`, name/threshold/active copied from `catalog.product.events`, `low` flag, the service's **outbox**, so stock events are keyed by productId). Every scan/reservation = one transaction (unit + `history` + `stock` + events). Scans need `Idempotency-Key` (py-common `IdempotencyStore`, Redis `inv:idem:*`, 24 h, replays 4xx too). Places via catalog `/internal/places?barcode=` cached in Redis `inv:place:*`. Unit barcodes `<productId>_<8 hex>`; a legacy label without a record is created on first stow. Assigned unit = off the shelf, must be returned before stow/pick/relocate. Low = threshold > 0 and available ≤ threshold. `/labels` `fileId` is `null` until document-svc (P6). Order-event consumer done in P5. Migration M04 must build `stock` for every product.
- **Orders (P5):** state machine in `order_svc/domain.py` must equal `tests/transitions/request_*.yaml` (test compares). Every change = one conditional update on (id, status, version) with history + outbox. **Admin fee charged once per request** (legacy rule), added to `agreement.total`; USD prices = BBD ÷ staff rate. Reservations are **async**: inventory consumes `order.accepted` (CIMH lines) / `order.probono_approved` / cancel/expire/agreement-rejected (release) and reports `stock.*` back; order lines show RESERVED/FAILED/RELEASED. Picks go order-svc → inventory **`/internal/picks`** (new; picker recorded). Admin fee via catalog **`/internal/fees`** (new). One cart per user via sparse unique `cartOf` (mongomock ignores partial indexes). File attachments don't bump `version` (async PDFs must not break If-Match). Customer re-choosing while AWAITING_AGREEMENT replaces the agreement. Same-org users read, never act (403); others 404.
- **Notifications (P6):** notification-svc is a worker only (`notification-consumer`); identity never had a temporary mailer, so before P6 no email was sent anywhere. Exactly once = consumer dedupe + per-recipient `ntf:sent:*` mark; new group starts at **latest** (py-common `run_service_consumer(start_at=)`), events > 48 h are skipped; codes parked in `ntf:code:*` until sent. New: event `order.quote_expiring` (order-jobs, once per expiry date), catalog `GET /internal/email-lists`, optional `customer` on `document.generated`. Erasure requests mail the `registration` list. **Staging-lite mail → Mailpit** (UI `ssh -N -L 18825:127.0.0.1:18825 kw-server`). Playwright `claimCode` reads codes from Mailpit (falls back to identity). Dev/CI e2e need `outbox-relay-identity` running (it wasn't: identity events never reached Kafka in the dev stack).
- **Documents (P6):** document-svc owns **no collection and no outbox**: metadata sidecar `protected/meta/<fileId>.json`, events published straight to Kafka (acks=all; upload refused + file removed if that fails), uploads also attached synchronously via order-svc `/internal/requests/{id}/files` so Accept works at once. order-svc `/internal/requests/{id}/access` now returns `allowed, canAct, status, type`; new `GET /internal/requests/{id}` (staff view) for PDFs; inventory → document-svc `POST /internal/labels` (fail-soft, `fileId` null). Scan **before** the type check (EICAR only matches at offset 0; every infected upload is quarantined); clamd down → 503. Generated file id = hash(eventId, kind). Commercial invoice only when ship-to ≠ BB. Dev: `SERVE_DIRECT=true` (no nginx), ClamAV behind profile `clamav`. **Staging-lite: `SCAN_ENABLED=false`** (owner, 2026-11-08); production scans.
